제가 지금 보험 GA 업무·정산 플랫폼을 준비하면서 가장 중요하게 보고 있는 부분이 **실제 보험업무에 필요한 데이터를 얼마나 정확하게 확보할 수 있느냐**입니다.

개발을 먼저 진행하기보다는, 실제 서비스를 만들 때 필요한 원천 데이터와 업무자료를 어떤 것까지 확보할 수 있는지 먼저 확인하고 싶습니다.

제가 생각하는 핵심 데이터는 크게 다음과 같습니다.

**1. 보험계약 관련 데이터**
- 계약번호
- 보험사
- 상품명 / 상품코드
- 계약일
- 계약상태
- 계약자 / 피보험자 관련 정보
- 보험료
- 납입기간
- 계약 유지 여부
- 실효·해지·부활 등의 상태정보

**2. 설계사 및 조직 관련 데이터**
- 설계사 기본정보 / ID
- 소속 GA / 지점 / 조직
- 설계사별 계약 실적
- 월별·기간별 실적
- 모집인별 계약 현황

- 설계사 ID
- 소속 GA
- 조직/팀
- 위촉일
- 자격 상태
- 담당 계약
- 실적
- 조직장 관계
- 수수료 지급 관계

**3. 수수료 관련 데이터**
이 부분이 특히 중요합니다.

- 상품별 수수료 기준
- 보험사별 수수료 기준
- 계약별 예상 수수료
- 잠정 수수료
- 확정 수수료
- 지급 예정 금액
- 실제 지급 금액
- 환수 금액
- 환수 사유
- 수수료 조정 내역

- 상품별 수수료
- 초년도 수수료
- 유지관리수수료
- 지급 회차
- 지급 예정금액
- 실제 지급금액
- 시책
- 보너스
- 조직수수료
- 지급일
- 정산 상태

즉, 단순히 "이 계약에서 얼마를 받는다"가 아니라

**예상 → 잠정 → 확정 → 지급 가능 → 실제 지급**

이렇게 실제 정산이 어떻게 변화하는지를 확인할 수 있는 데이터가 필요합니다.

**4. 보험사별 정산자료**
가능하다면 실제 보험사에서 GA에 제공하는 정산자료나 원장 형태의 자료가 필요합니다.

예를 들어
- 엑셀
- CSV
- PDF
- 보험사 시스템에서 내려받는 자료
- 기타 원장 데이터

등 실제 현장에서 사용하는 자료를 받아볼 수 있는지가 궁금합니다.

**5. 계약 유지 및 환수 관련 데이터**
수수료가 계약 이후에도 변경될 수 있기 때문에

- 계약 유지기간
- 실효
- 해지
- 환수
- 환수 예정
- 환수 완료
- 수수료 조정

같은 데이터도 확보가 가능한지 확인하고 싶습니다.

**6. 상품 데이터**
보험사별 상품정보도 가능하면 필요합니다.

- 상품명
- 상품코드
- 보장내용
- 보험료 관련 정보
- 판매기간
- 판매중/판매종료 여부
- 상품별 수수료 관련 정보

다만 이 부분은 실제 제공받을 수 있는 범위를 먼저 확인하고 싶습니다.

### 1. 보험계약 데이터

실제 GA에서 사용하는 계약 데이터가 어떤 구조인지 궁금합니다.

예를 들면,

- 계약번호
- 보험회사
- 상품코드
- 상품명
- 계약일
- 보험료
- 납입기간
- 계약상태
- 설계사
- 계약 유지기간
- 실효·해지 여부

이런 기본적인 **Contract Data, 계약 원장** 같은 자료가 실제로 있을까요?

실제 고객 개인정보는 필요 없습니다.

개인정보가 있다면 가상의 고객정보로 바꾼 **샘플 데이터나 비식별 데이터**만 있어도 충분합니다.

### 2. 설계사 및 조직 데이터

그리고 설계사 쪽도 실제로 어떤 데이터가 관리되는지 알고 싶습니다.

예를 들면

- 설계사 ID
- 소속 GA
- 조직/팀
- 위촉일
- 자격 상태
- 담당 계약
- 실적
- 조직장 관계
- 수수료 지급 관계

같은 **Agent Data / Organization Data**입니다.

특히 조직 구조와 설계사별 실적이 실제 시스템에서 어떻게 연결되는지가 중요할 것 같습니다.

---

### 3. 수수료 데이터

제가 가장 중요하게 보는 부분 중 하나가 **Commission Data**, 즉 수수료 데이터입니다.

실제로 보험사에서 GA로 내려오는 수수료 자료나 GA에서 설계사에게 정산하는 자료가 있다면 보고 싶습니다.

예를 들면,

- 상품별 수수료
- 초년도 수수료
- 유지관리수수료
- 지급 회차
- 지급 예정금액
- 실제 지급금액
- 시책
- 보너스
- 조직수수료
- 지급일
- 정산 상태

이런 자료입니다.

제가 알고 싶은 것은 단순히 “몇 %를 준다”가 아니라,

**어떤 데이터를 가지고 어떤 계산 과정을 거쳐서 최종 지급금액이 만들어지는지**입니다.

---

### 4. 정산 원장 / Settlement Data

그리고 가능하다면 실제 **Settlement Ledger, 정산 원장**도 샘플 형태로 보고 싶습니다.

예를 들어

> 계약 발생  
> → 수수료 계산  
> → 지급 예정  
> → 보험사 확정  
> → GA 정산  
> → 설계사 지급

이런 과정이 실제로 어떤 데이터로 관리되는지 궁금합니다.

제가 개발자에게도 이 부분을 중요하게 이야기하고 있습니다.

**“예상 수수료와 확정 수수료를 분리해야 하지 않느냐”**

라는 부분입니다.

처음부터 예상금액을 확정금액처럼 보여주면 나중에 실제 보험사 정산과 차이가 날 수 있으니까요.

---

### 5. 유지 및 환수 데이터

그리고 **Clawback, 환수 데이터**도 필요합니다.

보험계약이 중도 해지되거나 실효되었을 때,

- 어떤 조건에서 환수가 발생하는지
- 어느 시점에 환수되는지
- 얼마가 환수되는지
- 이미 지급한 수수료에서 어떻게 차감하는지
- 미수금이 다음 정산으로 넘어가는지

이런 실제 데이터 구조가 궁금합니다.

특히 이 부분은 제가 생각하기에는 고정된

**“1년차 100%, 2년차 80%”**

같은 방식으로 프로그램에 박아 놓는 것보다,

**보험사 + 상품 + 계약일 + 수수료 종류 + 지급회차 + 계약상태**

등에 따라 계산할 수 있는 **Rule Engine** 구조가 맞는 것 같습니다.

실제 현장에서는 어떻게 관리하는지 자료가 있다면 보고 싶습니다.

---

### 6. 상품 데이터

그리고 보험상품 데이터도 중요할 것 같습니다.

예를 들어

- 보험회사
- 상품코드
- 상품명
- 상품 버전
- 판매기간
- 보장내용
- 보험료
- 납입기간
- 갱신 여부
- 상품별 수수료 기준

등입니다.

특히 상품은 시간이 지나면서 변경될 수 있기 때문에,

**Product Version / Rule Version**

개념으로 과거 계약의 기준을 보존해야 하는지도 확인하고 싶습니다.

### 7. 제가 가장 궁금한 것은 결국 이것입니다.

제가 생각한 데이터 말고,

**실제 보험 GA 플랫폼을 만든다고 했을 때 개발자 입장에서 반드시 필요한 데이터가 무엇인지**

알고 싶습니다.

예를 들어 제가 생각하지 못한

- 보험사 원천 데이터
- 상품 마스터
- 수수료 Rule
- 정산 원장
- 환수 원장
- 설계사 실적
- 계약 상태 이력
- 조직 관계
- 고객 동의/상담 기록
- 변경 이력
- Audit Log

같은 데이터가 더 필요할 수도 있을 것 같습니다.

그래서 가능하면 재일 씨가 보시기에

**“이 정도 데이터가 있어야 실제 GA 시스템을 만들 수 있다.”**

하는 기준을 한번 잡아주셨으면 좋겠습니다.

## 그리고 데이터가 있다면 형태도 궁금합니다.

꼭 완성된 API가 아니어도 괜찮습니다.

예를 들어

**Excel / CSV / DB / API / JSON**

중 어떤 형태로 받을 수 있는지,

그리고 실제 개발에 연결할 수 있는 **Source Data인지 단순 참고용 Sample Data인지**

도 구분해서 알고 싶습니다.

---

## 제가 확인하고 싶은 건 딱 네 가지입니다.

**첫째, 어떤 데이터를 확보할 수 있는지.**

**둘째, 그 데이터를 어떤 형태로 받을 수 있는지.**

**셋째, 실제 개발에 사용할 수 있는 원천 데이터인지.**

**넷째, 부족한 데이터가 있다면 무엇을 추가로 확보해야 하는지.**

이 네 가지를 먼저 정리하고 싶습니다.

그다음에야 개발자하고

**DB Schema → API → Rule Engine → Settlement Engine → CRM → 관리자 화면**

이런 식으로 실제 개발 범위를 잡는 게 맞다고 생각합니다.

그리고 혹시 실제 소스코드나 기존 시스템의 로직을 공유할 수 있는 범위가 있다면 그것도 궁금합니다.

소스코드 자체가 어렵다면 괜찮고요.

오히려 제가 필요한 것은 소스코드보다 **실제 업무 데이터의 구조와 정산 로직**입니다.

개인정보나 영업상 민감한 자료는 당연히 필요 없고,

**비식별화된 샘플 데이터와 실제 업무에서 어떤 항목을 가지고 계산하는지만 알 수 있어도 개발 방향을 잡는 데 상당히 도움이 될 것 같습니다.**

제가 지금 만들려는 게 단순히 화면만 예쁘게 만드는 앱이 아니라,

**실제 GA에서 사용할 수 있는 계약관리 + 설계사관리 + CRM + 수수료 정산 + 환수관리 시스템**

을 목표로 하고 있어서요.

그래서 개발을 시작하기 전에 **실제 현장에서 사용하는 데이터와 업무 프로세스를 먼저 확인하고 싶습니다.**

재일 씨가 가지고 있거나 제공 가능한 자료가 어느 정도까지 있는지부터 한번 이야기해보고 싶습니다.
